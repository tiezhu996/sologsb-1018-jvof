# 声律场 · 口语发音与韵律练习工作台

使用 Svelte 与 Skeleton 从零实现的口语练习工作台。学习者录入句子、划分意群并标注重音、停顿和语调，随后录音、选择回听范围、逐段比较偏差；学生在家练完的录音/意群/错词打成**可离线提交的练习包**，与学校电脑里教师的**逐段反馈**双向合并。

## 功能

- 句子录入、标点智能切分、意群增删与排序，每次改顺序都生成一个**顺序版本**（历史版本可回看）。
- 逐意群标注重音词、重音强度、停顿毫秒数和语调走向。
- 调用浏览器麦克风录音，支持多轮尝试；未授权麦克风时保留可校对的离线模拟轮次。
- 每一轮尝试独立保存回听起点、终点、准确度、节奏、偏差、自评和错词分类。
- 教师可按意群留下多轮反馈，并可**改写**或**撤回**（撤回以墓碑同步，其他设备的旧副本不会复活）。
- 练习进度、目标轮次、准确度、偏差和错词分类统计。

### 多设备离线同步（核心）

- **练习包**：每轮录音、意群顺序、错词、反馈各自打成 `OutboxBundle`，离线即可入队，持久化在 IndexedDB 的 outbox 仓。
- **录音去重**：录音按内容 SHA-256 寻址；同一录音重复提交，服务端只保留一份。
- **录音、意群顺序、错词排队上传**：录音切成 256 KiB 分片逐片上传；错词/反馈是独立轻量包，不等整轮重交。
- **断点续传**：每个分片收到确认后把 `ackedChunk` 落库；重开页面先查服务端实际收到的分片数，从断点补传，已传部分不重传。
- **意群改序与反馈锚定**：学生调整意群顺序后产生新版本，新旧版本都保留；教师按旧顺序留的反馈仍锚定原来的意群 id（而不是位置）。
- **待处理区**：反馈锚定的意群被彻底删除（不属于任何顺序版本）时，进入"待处理反馈"，可由教师/学生重新锚定到现存意群。
- **撤回/改写墓碑**：撤回或改写反馈会下发 `deletedAt` 墓碑，强制覆盖各端旧内容；旧设备重传的过期练习包也不能让它复活。
- **断网恢复**：断网时练习包留在本机，联网后（手动点"立即同步"、`online` 事件或每 20 秒轮询）自动续传；已传分片与已合并反馈都不会丢。

界面提供一个"模拟断网 / 清空模拟云端"开关，便于在单浏览器里演示断网排队与恢复续传。

## 同步架构

| 文件 | 职责 |
| --- | --- |
| `src/types.ts` | 领域模型 + 练习包/快照协议类型 |
| `src/db.ts` | IndexedDB v2 多仓封装（meta / project / outbox / audio） |
| `src/storage.ts` | 项目、录音库、outbox、设备身份读写，含 v1 单仓数据迁移 |
| `src/server-core.ts` | **纯函数**服务端合并规则（墓碑、顺序版本、待处理区、分片幂等），不依赖 DOM |
| `src/mock-server.ts` | 用独立 IndexedDB 库扮演云端；规则复用 `server-core`，接口与真实 HTTP 同构 |
| `src/runtime.ts` | 同步引擎的可注入运行时（存储 + 网络），生产用真实实现，测试注入内存实现 |
| `src/sync.ts` | 打包、分片断点续传、拉取快照、双向合并、墓碑处理 |
| `src/sync.e2e.test.ts` / `src/server-core.test.ts` | 规则与端到端测试 |

真实接入后端时，只需用同样签名的 HTTP 版本替换 `src/mock-server.ts` 的 `pushBundle / uploadChunk / getChunkStatus / fetchSnapshot / downloadAudio`，客户端引擎无需改动。

## 技术栈

- Svelte 4 · Vite 5 · TypeScript · Skeleton 2 · Tailwind CSS 3
- IndexedDB（录音 Blob 独立成仓，按内容哈希去重），不可用时退化 localStorage（不存原始录音）
- Service Worker 缓存应用壳

## 本地开发

```bash
npm install
npm run dev
```

Vite 开发服务器使用本地端口 `5175`，该端口不构成宿主映射。容器生产环境仅监听 `80`。

## 测试与构建

```bash
npm test     # node --test：服务端合并规则 + 客户端同步引擎端到端（内存替身，无需浏览器）
npm run build
npm run preview
```

构建结果位于 `dist/`。

## Docker

```bash
docker build -t sologsb-1018 .
docker run --rm -p 10018:80 sologsb-1018
```

最终镜像使用 nginx 在容器 `80` 端口提供构建产物。宿主端口由根编排文件维护，源码和 Dockerfile 没有硬编码宿主端口。

## 本地数据与麦克风

- 录音 Blob 存于 IndexedDB 的 `audio` 仓（按 SHA-256 去重）；项目、outbox、设备身份各占一仓。
- IndexedDB 不可用时退化为 `localStorage`，浏览器安全限制下不保存原始录音 Blob。
- 首次打开 v2 会自动把 v1 单仓里的项目与内联录音迁移到新结构，迁移成功后删除旧库。
- 生产页面首次加载后由 Service Worker 缓存，离线仍可继续标注、录音、打包；清除站点数据会永久删除本机练习（模拟云端数据可单独清空）。
